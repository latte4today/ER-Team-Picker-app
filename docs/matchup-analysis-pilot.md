# 화면 반응 개선과 실제 조합 상성 분석 — 2026-10-13

사용자의 박치기·쌍포·3원딜 분류를 고정하지 않고 실제 캐릭터 3명, 각 무기·코어와 상대 빌드를 분석했다. 현재 결과는 특정 상대에 대한 유불리를 공개하기에 부족하다. 상성이 없다는 결론이 아니라 이번 표본과 방법으로 확인되지 않았다는 의미다.

## 실행한 분석

기존 공식 API 수집 자료에서 게임 버전 12.5 계열 랭크 경기, 서로 다른 실험체 3인 팀만 사용했다. 32,571팀, 4,260경기이며 해당 자료의 시각 범위는 2026-10-01~10-12다. 경기당 최소 4팀이 관측되어야 포함했다. 전체 로비가 완전히 수집되지 않은 경우도 있으므로 전체 모집단 대표성을 보장하지 않는다. 원본 개인정보와 경기 식별자는 공개하지 않는다.

- 시간순으로 경기 전체를 2,982 / 639 / 639경기(훈련 / 검증 / 최종 평가)로 분리했다. 같은 경기의 팀이나 비교 쌍을 서로 다른 구간에 넣지 않았다.
- 기준 모델: 캐릭터+무기 효과, 실제 코어 효과, 아군 두 실험체의 결합, 경기 전 팀 평균 MMR 차이.
- 상대 모델: 기준 모델에 아군과 적의 실제 무기·코어 빌드 간 9개 대응 효과를 추가했다. 새로운 조합에도 학습한 구성원 효과를 공유하므로 특정 3인 조합의 독립 승률과는 다르다.
- 피해량·처치 수 등 경기 후 통계는 예측 입력에서 제외했다. 훈련 자료만으로 특징 사전을 만들고 검증 자료로 정규화 강도를 선택했다.
- 로비 내 두 팀의 최종 순위만 비교했다. 팀당 교전 승률로 해석할 수 없다. 부활, 제3팀 개입, 장비·크레딧 차이, 교전 시점은 통제하지 못한다.
- 경기당 합계 가중치를 1로 두고, 평가 경기 단위 재표집으로 차이의 신뢰구간을 구했다. 같은 경기의 비교 쌍들을 독립 표본으로 세지 않았다.

| 평가 지표 | 기준 모델 | 상대 효과 추가 |
|---|---:|---:|
| 최종 순위 순서 예측 정확도 | 52.03% | 52.01% |
| AUC | 0.5268 | 0.5270 |
| 로그 손실(낮을수록 좋음) | 0.691978 | 0.691948 |

상대 효과의 로그 손실 차이는 −0.0000297이며, 95% 경기 재표집 구간은 −0.0000886~+0.0000318로 0을 포함한다. 이 실험에서 성능 개선을 확인하지 못했다. 표시용 점수나 추천 가중치로 적용하지 않았다.

## 분석을 발전시킬 방법

1. 실제 세 실험체·무기·코어와 함께 진입 능력, 진입 저지, 보호·회복, 지속 피해, 폭발 피해, 사거리, 기동성 등 연속적인 전투 특성을 구성한다. 고정된 탱/딜 숫자 대신 각 빌드와 팀의 전투 구조를 표현한다. 코어에 따라 역할이 달라지는 경우도 반영한다. 스킬 정의로 만든 특성은 전술 가설이며 통계 검증 결과와 구별한다.
2. 관측 자료에서 팀 특성을 군집화하고 각 군집의 대표 실제 조합을 확인해 이름을 붙인다. 분류 수는 분리된 검증 자료의 안정성과 설명 가능성으로 정한다. 쌍포 등 경험적 이름을 처음부터 정답으로 강제하지 않는다.
3. 더 넓은 티어·시각·패치 자료를 모으고 패치별로 검증한다. 소수 빌드는 구성원과 전투 특성으로 정보를 공유하되 불확실성을 크게 표시한다. 같은 로비에 있던 조합이라는 것과 실제 싸운 조합이라는 것을 구별한다.
4. 실제 교전 상대 팀, 교전 시작·종료, 전멸·이탈, 시작 장비·크레딧, 제3팀 개입을 확인할 수 있는 기록이 있어야 직접 교전 상성을 분석할 수 있다. 공개 API에 없는 기록은 임의로 복원하지 않는다. 필요하다면 사용자가 확인한 리플레이 또는 교전 기록으로 별도 검증 표본을 만든다.
5. 충분한 표본과 별도 미래 경기 검증, 신뢰구간, 다중 비교 보정 후에만 앱에 상대 조합 유불리를 표시한다. 현재는 근거 부족으로 공개 유불리 표시를 보류한다.

## 수집 개선

공식 API의 killDetails/deathDetails(실험체 코드별 처치·사망 횟수)를 기존 수집 요청에서 추가 보존하고 학습 자료 내보내기까지 연결했다. 정수 코드·횟수만 허용하며 닉네임·사용자 ID·구식 killerUserNum을 포함하지 않는다. 누락 필드는 누락으로 유지한다. 신규 API 요청, 유료 서비스, 추가 자동 실행을 만들지 않았다. 다음 기존 수집부터 적용되며 과거 누락 정보가 복구된 것은 아니다. 이 집계도 상대 팀의 세 멤버나 교전 시점을 알려주지는 않는다.

## 화면 개선

탭과 제목을 먼저 전환한 다음 본문을 그린다. 빠르게 여러 탭을 누르면 마지막 선택만 처리한다. 숨겨진 실험체 목록·경기 평가·유니온을 매번 다시 그리지 않는다. 조합 구성과 랭킹의 실제 화면 요소 및 스크롤 위치를 각각 보관한다. 변경 없는 언어 번역과 랭킹 결과를 재사용한다. 랭킹 통계를 두 번 계산하던 것을 한 번 계산하고 상위 16개만 유지하며, 데이터 교체 시 캐시를 갱신한다. 숨겨진 전체 팀 추천의 비동기 결과가 랭킹 화면을 덮지 않도록 막았다.

이 PC의 동일 자료(128,874행) 보조 측정: 기존 전체 순위 처리 약 540~923ms/회, 개선 후 최초 약 410ms, 동일 자료 재조회는 측정 단위상 0.0ms. 이는 통계 함수 측정이며 클릭부터 전체 화면 완성 시간이나 모든 기기에서 0ms라는 뜻은 아니다. 첫 진입 계산은 남지만 화면 전환 이후 처리하고 반복 전환은 결과를 재사용한다.

## 재현 및 근거

분석 도구: tools/analyze_matchup_outcomes.py. numpy/scipy/scikit-learn 필요. 로컬 기존 Python 라이브러리로 실행했다. raw JSONL을 저장소에 커밋하지 않는다. 실행 예: python tools/analyze_matchup_outcomes.py --in NORMALIZED.jsonl --out REPORT.json --version 12.5

[공식 ER API 스키마](https://developer.eternalreturn.io/static/media/OpenAPI_EN_20260917_01.html)는 처치·사망 코드 집계와 팀 MMR 정의를 제공한다. [scikit-learn 교차 검증 문서](https://scikit-learn.org/stable/modules/cross_validation.html)를 참고해 훈련·검증·평가 자료를 분리했고, [LogisticRegression 문서](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html)의 모델을 사용했다. 결과 수치는 이번 로컬 실험에서 산출했다.
